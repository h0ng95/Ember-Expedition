# 전투별 난도 곡선 점검

v0.48 구현·검증은 [최신 기록](../../docs/design-v0.48/HANDOFF.md)을 따른다. `-Rules v046`은 이전 규칙, 기본값은 현재 규칙이다. `-ComparePrevious`는 변경한 전투에서 같은 편성의 v0.46 비교도 추가한다. `run-regression.ps1`은 저장·이전 편성 보존·서리 연쇄 규칙을 검증한다. 아래 v0.47 증원 실험은 당시 기준 커밋으로만 재현하며 현재 채택안이 아니다.

이 도구는 실제 원정 진행과, 같은 편성을 다른 전투에 투입하는 비교를 분리한다. 게임의 난도나 저장 형식을 변경하지 않는다.

```powershell
./tests/DifficultyCurve/run.ps1 -FirstSeed 49501 -Count 4 -ReportPath .local-tools/v047/fixed-party.json
```

4개 시작 편성 × 3개 성장 목표(final, H-04, H-05) × 3개 연구 계열 × Count개 시드다. 연구는 11전투부터 전투당 하나씩 구매한다. 실제 경로의 패배는 등불을 소비하며, 승리만 보상을 지급한다. 완주 또는 등불 소진 시 종료한다.

각 전투의 첫 준비 상태를 복사해 이전·다음 전투와 싸운다. 지역의 세 번째 전투(3·8·13·18·23·28)에서는 해당 지역 보스도 비교한다. **복사한 상태에서 전투 번호만 바꾸는 비교는 실제 진행 가능한 원정이 아니다.** 성장·배치·연구가 같은 상태에서 적 편성만 비교하기 위한 실험이다. 이 전투는 본 원정의 골드·등불·난수·진행도에 영향을 주지 않는다.

출력의 `actualBattles`와 `counterfactualBattles`를 따로 보고한다. `rows`는 도달한 현재 전투의 편성을 기준으로 한 조건부 통계다. 다른 행은 다른 표본이므로 행 사이의 승리 비율만으로 난도 역전을 단정하면 안 된다. 같은 행의 `current`, `next`, `boss`가 같은 편성을 사용한 비교다.

`encounters`에는 실제 생성된 적 수·체력·일반 공격 DPS와 배치를 기록한다. 일반 공격 DPS에는 보스 패턴·상태 이상·방어력·대상 분산이 포함되지 않으므로 종합 난도 점수로 사용하지 않는다.

## 증원 실험 재현

```powershell
./tests/DifficultyCurve/run-count-trial.ps1 -FirstSeed 49001 -Count 4
```

현재 코어를 `.local-tools/v047`에 복사하고, 별도 실행 파일에서만 적 수를 늘린다. 실제 게임 소스는 바꾸지 않는다. 기존 `ResearchRegions/matrix.cjs`를 이용해 각 버전 224 × Count개 원정을 실행한다. 이번 결과의 기준 커밋은 `5f89a55`이며, 이후 코어가 바뀌면 같은 결과를 보장하지 않는다.

증원 대상은 6·7·11·12·13·14·16·17·19·20·21·22·24·26·27·29전투다. 대부분 한 명, 11전투는 두 명을 추가한다. 원거리 적 3명의 위치 중복을 피하기 위해 시험용 폐광 원거리 배치도 3열로 나눈다. 이 변경의 정확한 내역은 `prepare-count-trial.cjs`에 있다.

이는 채택된 밸런스안이 아니다. [실험 결과와 판단](../../docs/design-v0.47/difficulty-audit.md)을 먼저 읽는다.
